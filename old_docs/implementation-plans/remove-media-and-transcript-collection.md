# 動画・音声・字幕データ廃止 実装計画

## 1. 背景と目的

YouTube Stream Analyzer の収集対象から、動画ファイル、音声データの解析、字幕・文字起こしを廃止する。

動画・音声は取得・保存・解析コストが大きい一方、現時点で想定する分析価値に見合わない。字幕も今後の収集・表示・検索対象に含めない。以後の中心データは、配信メタデータ、ライブチャット、およびそこから導出する時系列指標と切り抜き候補とする。

この変更では、実装済みの字幕機能を収集処理、内部 Gateway、Main API、PostgreSQL、Web UI、テスト、運用設定、ドキュメントから一貫して除去する。また、未実装の動画・音声ファイル保存および音声解析を将来計画、責務、データモデルから除去し、誤って再導入されないようにする。

## 2. ユーザーシナリオ

1. 利用者が終了済み配信を登録する。
2. 配信メタデータとライブチャットの収集を開始する。
3. `metadata` と `chat_replay` の工程別状態を確認する。
4. 収集後、YouTube 埋め込みプレーヤーとチャットを同じ経過時刻で確認する。
5. チャット項目またはチャット検索結果から、プレーヤーの該当時刻へ移動する。

字幕の有無、字幕の取得状態、字幕件数、字幕検索結果は通常画面に表示しない。字幕がないこともエラーや部分失敗として扱わない。

## 3. スコープ

### 3.1 変更するもの

- 新規の手動収集と予約後収集を `metadata`、`chat_replay` の二工程にする。
- Worker の字幕取得、トラック選択、ページング、保存、エラー分類、設定を削除する。
- YouTube Data Gateway の字幕エンドポイント、字幕 Provider、字幕モデル、字幕固有エラーを削除する。
- Main API の字幕一覧 API と字幕 Repository を削除する。
- 配信内検索と時刻範囲取得をチャット専用の契約・実装へ変更する。
- Web UI から字幕表示、字幕状態、字幕文言、字幕検索結果を削除する。
- PostgreSQL の字幕データを削除し、字幕スキーマを廃止する forward migration を追加する。
- 字幕専用 stub、fixture、設定値、依存パッケージが不要になれば削除する。
- M3、M4 の E2E を、動画とチャットの同期・検索・再収集・予約後収集を確認するシナリオへ更新する。
- ロードマップ、マイルストーン、アーキテクチャ、ADR、契約説明、完了デモ、環境構築文書、公開ドキュメントを新方針に更新する。
- 動画・音声ファイル保存、音声抽出、独自文字起こし、音声解析を将来構想と収集成果物から削除する。

### 3.2 維持するもの

- YouTube Data API から取得する配信メタデータ。
- ライブチャットリプレイの取得、正規化、保存、再試行。
- YouTube IFrame API による埋め込み再生。これは動画ファイルの取得・保存ではなく、チャットの時刻確認に使う閲覧機能である。
- チャット項目およびチャット検索結果から埋め込みプレーヤーへのシーク。
- YouTube のサムネイル URL や元配信 URL の保持。
- Collection Job の claim、lease、heartbeat、失敗記録、工程単位再試行という基本モデル。
- PostgreSQL による、配信メタデータ、ライブチャット、ジョブ、予約、将来の分析結果の永続化。

### 3.3 対象外

- チャットから算出する分析指標や切り抜き候補アルゴリズムの新規実装。
- YouTube 埋め込みプレーヤー自体の廃止。
- ライブチャット取得方式の変更。
- メタデータ項目の再設計。
- 字幕の代替となる独自文字起こしや外部 AI 解析の導入。
- この変更と無関係な UI 改修やコード整理。

## 4. 現状と影響範囲

### 4.1 収集オーケストレーション

- Main API は全工程ジョブを `metadata / chat_replay / transcript` で作成する。
- 予約後収集も同じ三工程を要求する。
- Worker は `transcript` 工程を判定し、Gateway 呼び出しと PostgreSQL 保存を行う。
- Job の取得順序と集約状態には `transcript` 固有の分岐がある。

### 4.2 YouTube Data Gateway

- チャットと字幕を同一サービスで提供している。
- 字幕トラック一覧と字幕セグメントページの二つの内部 API がある。
- 字幕 Provider、正規化モデル、エラー分類、fixture、テスト、依存関係がある。

Gateway サービスはチャットリプレイ取得のため引き続き必要であり、サービス全体は削除しない。

### 4.3 Main API とデータベース

- 字幕トラックと字幕セグメントを保持する専用 schema がある。
- 字幕一覧 API がある。
- 配信内検索はチャットと字幕を `UNION ALL` し、cursor の種別にも `transcript` を含める。
- 時刻範囲取得、Collection Step、OpenAPI enum に字幕が含まれる。
- M4 デモレポートが字幕件数と字幕必須条件を持つ。

### 4.4 Web UI

- 収集開始の説明、工程表示、失敗表示に字幕が含まれる。
- 同期閲覧はプレーヤー、チャット、字幕を扱う。
- 配信内検索はチャットと字幕の横断検索として表示・型定義されている。
- E2E は字幕の正常取得、データなし、部分失敗、工程再実行、字幕からのシークを検証する。

### 4.5 ドキュメント

- プロダクトロードマップ、アーキテクチャ、マイルストーンの価値定義が字幕を前提にしている。
- M3 の ADR、データモデル、完了デモが字幕実装の正本になっている。
- 動画・音声ファイル、FFmpeg、Blob Storage、`audio` 工程が将来構想として複数箇所に残っている。

## 5. 実装上の決定

### 5.1 収集契約

- 新規の全工程収集は `metadata`、`chat_replay` の順とする。
- チャットだけを再収集する既存操作は維持する。
- 字幕がないことによる `no_data`、`partial`、字幕固有エラーは新規ジョブでは発生させない。
- 既存 DB に残る `transcript` Step は履歴として API から読み取れてもよいが、Worker は新たに claim・実行しない。移行後に未完了の字幕 Step がジョブを永久に未完了にしないよう、migration で終端化または削除する。
- 旧クライアントからの `transcript` 工程再実行要求は `404` または既存の非再実行可能応答へ落とし、字幕処理を復活させない。最終的な OpenAPI からは値自体を削除する。

### 5.2 API と検索契約

- 字幕一覧 endpoint は削除する。互換用の空レスポンス endpoint は残さない。
- 配信内検索 endpoint は維持し、返却項目をチャット専用に縮小する。
- 検索結果の `type` が単一値になって情報を持たない場合は削除する。既存 UI と cursor の移行を小さく保つ方が安全なら、最初の互換コミットでは `chat` 固定で残し、次の契約整理コミットで削除する。
- 字幕専用の終了時刻と言語コードはレスポンスから削除する。チャットの投稿者情報と経過時刻は維持する。
- 時刻範囲 endpoint が画面で利用中ならチャット専用へ縮小し、未使用なら endpoint 自体を削除する。実装時に呼び出し元を再確認し、OpenAPI とコードを同一コミットで一致させる。

### 5.3 データ削除

- 既存字幕は保持・移行せず削除する。本変更は字幕データ廃止であり、archive table や JSON artifact への退避は行わない。
- 適用済み migration は書き換えず、新しい forward migration で字幕 schema を `CASCADE` せず明示的な順序で削除する。
- migration の前に API、Worker、デモレポートから字幕 table 参照をなくし、展開順序に依存する短い不整合期間を避ける。
- migration の Down は schema と table 構造を復元できても、削除済み字幕本文は復元できないことを明記する。

### 5.4 動画と音声

- 「動画ファイル廃止」はサーバーへの動画 download、永続保存、配信 artifact 化を行わないという意味とする。
- 「音声データの解析廃止」は音声抽出、音声ファイル保存、音声認識、音響特徴量解析を導入しないという意味とする。
- ブラウザの YouTube 埋め込みプレーヤーは保存データではないため維持する。
- Azure Blob Storage と FFmpeg をアーキテクチャの採用技術から外す。配信データだけでなく、コンテキスト出典スナップショット等の将来用途にも Blob Storage を使用しない。
- 永続化先は PostgreSQL に限定する。将来、大容量ファイル保存が具体的に必要になった場合は、その時点で要件と保存先を改めて設計する。

### 5.5 ADR と正本

- 過去の ADR は当時の決定記録なので本文を事後改変して決定自体を消さない。
- 新しい ADR で字幕収集・動画音声処理を廃止し、M3 ADR の該当決定を supersede する。
- 現行方針を表すロードマップ、アーキテクチャ、マイルストーン、契約、完了デモは新方針へ全面更新する。

## 6. 小さなコミットによる実装順序

各コミットは `make check` の対象を通し、少なくとも変更した層のテストが成功する状態にする。

### Commit 1: 廃止方針を ADR と正本へ反映する

- 新 ADR に、廃止理由、対象データ、YouTube 埋め込み再生を維持する境界、既存字幕を削除する判断を記録する。
- ロードマップとマイルストーンを、メタデータ・チャット中心の価値と完了条件へ変更する。
- M3 を「動画とチャットを同期して場面を探す」へ再定義する。
- 後続マイルストーンから字幕、音声、動画ファイル依存を除去する。
- この時点では実装契約が旧状態であることを、変更中の文書上で混同しないようにする。

### Commit 2: 新規ジョブを二工程へ縮小する

- Main API の全工程ジョブと予約収集の要求工程を `metadata / chat_replay` に変更する。
- Collection Repository と予約収集のテスト期待値を更新する。
- 新規ジョブが字幕 Step を生成しない統合テストを追加する。
- 既存の字幕 Step を読み取れる Job/Step の汎用構造は、この時点では維持する。

### Commit 3: 旧字幕 Step を安全に終端化する

- migration で、未完了の `transcript` Step と関連 attempt を廃止済みとして終端化または削除する。
- 親 Job の状態・進捗・要求工程を二工程基準で再計算する。
- 完了済み Job が回帰せず、未完了 Job が字幕待ちで停止しない migration テストを追加する。
- Worker の claim 対象から `transcript` を外し、未知または廃止済み工程を誤実行しないテストを追加する。

### Commit 4: Worker の字幕実行経路を削除する

- 字幕 Gateway client、トラック選択、ページング、保存 Repository を削除する。
- Worker 起動処理から字幕 handler と字幕設定を削除する。
- 字幕固有の unit/integration tests を削除し、残る Job、設定、チャット収集テストを更新する。
- `.env.example`、Worker README、deploy 設定から字幕用 URL、timeout 等を削除する。

### Commit 5: Gateway をチャット専用へ縮小する

- 字幕 track/segment endpoint と Provider を削除する。
- 字幕モデル、正規化、エラー mapping、fixture を削除する。
- Gateway の OpenAPI と README をチャットリプレイ専用へ更新する。
- 不要になった字幕取得ライブラリがチャット側で使われていない場合だけ依存から削除する。
- health/readiness と実チャット取得テストが引き続き成功することを確認する。

### Commit 6: Main API の字幕読み取りを削除する

- 字幕 handler と Repository、API route を削除する。
- OpenAPI から字幕一覧 endpoint、字幕固有 schema、enum 値を削除する。
- 配信内検索をチャット専用 SQL、cursor、response へ変更する。
- 時刻範囲 API を利用状況に応じてチャット専用化または削除する。
- API handler と DB integration tests を、チャットのみの外部振る舞いへ更新する。

### Commit 7: Web UI をチャット専用表示へ変更する

- 収集案内を「ライブチャットを収集して動画と同期」に変更する。
- 現在工程、件数、失敗表示から字幕の分岐と文言を削除する。
- 同期表示をプレーヤーとチャットの組み合わせへ整理する。
- 検索 UI の型、ラベル、empty state、placeholder、結果 metadata をチャット専用へ変更する。
- 字幕なし、字幕部分失敗、字幕再実行の操作を画面から除去する。
- 既存のユーザー変更がある `styles.css` と `m3-youtube-player.spec.ts` は上書きせず、差分を確認して統合する。

### Commit 8: 字幕 schema と補助ツールを削除する

- 新しい forward migration で字幕 table、index、schema を明示的に削除する。
- 字幕 stub command と M4 デモレポートの字幕件数・必須 flag・秘密情報文言を削除する。
- repository 検査や deployment check に字幕固有の期待値があれば更新する。
- 空 DB への全 migration と、既存 schema からの forward migration の両方を検証する。

### Commit 9: E2E と完了デモを新しい縦断シナリオへ更新する

- M3 E2E を `metadata / chat_replay` の収集、DB 保存、同期表示、チャットからのシーク、チャット検索、再収集時の重複排除へ更新する。
- M4 E2E を予約、アーカイブ待機、二工程収集、チャット表示・検索の完走へ更新する。
- 字幕なし、字幕部分失敗、字幕工程再実行のテストを削除する。
- チャットなしを `no_data` とする既存振る舞いは、仕様どおりなら独立したテストとして維持する。
- Playwright の fixture server と起動環境から字幕 stub を外す。

### Commit 10: アーキテクチャと運用文書を最終状態へ同期する

- アーキテクチャ図、データストア、Gateway 責務、技術選定から字幕、Azure Blob Storage、配信動画・音声保存、FFmpeg、音声解析を除去する。
- Context Worker を含む全コンポーネントから Blob Storage への接続と出典スナップショット保存の計画を除去し、永続化先を PostgreSQL に統一する。
- M3/M4 データモデルと完了デモを、チャット専用の収集・同期・検索へ書き換える。内容が字幕専用で不要になる文書は削除し、参照リンクも更新する。
- ローカル開発、Railway 検証、Gateway 契約説明、公開 HTML、図版を更新する。
- `rg` で字幕、音声解析、動画ファイル保存の残存記述を監査し、過去 ADR の履歴記述など意図した残存だけを一覧化する。
- `make check` を実行し、完了デモ手順を実データで確認できる状態にする。

## 7. テスト方針

テストは削除した内部 class や function の不存在ではなく、利用者・サービス間で観測できる振る舞いを確認する。

### 7.1 Main API / PostgreSQL

- 新規全工程 Job に `metadata` と `chat_replay` だけが含まれる。
- 予約から生成した Job も同じ二工程になる。
- チャット検索が安定した cursor でページングできる。
- API 契約に字幕 endpoint と字幕 enum が存在しない。
- 既存字幕データを持つ DB に migration を適用でき、他の stream、chat、collection、reservation データは保持される。
- 未完了の旧字幕 Step が親 Job を停止させない。

### 7.2 Worker / Gateway

- Worker がメタデータとチャット工程を順番どおり完了する。
- チャットの一時失敗、恒久失敗、認証失敗、データなしを既存契約どおり分類する。
- 廃止済みまたは未知の工程を claim しても字幕処理を起動しない。
- Gateway が実装済みのチャット paging、continuation、正規化、エラー分類を維持する。

### 7.3 Web UI / E2E

- 収集前、実行中、成功、失敗を利用者が識別できる。
- 画面に字幕取得可否、字幕工程、字幕件数、字幕検索 UI が表示されない。
- チャット項目と検索結果から YouTube プレーヤーを該当時刻へ移動できる。
- 再収集してもチャットが重複しない。
- M4 の予約から収集・閲覧までが字幕 Gateway なしで完走する。

### 7.4 文書・静的検査

- OpenAPI 検証が成功する。
- 図版と公開ドキュメントの生成・リンク検査が成功する。
- 字幕関連語の残存は、新 ADR に記録する過去判断の参照や migration 名など、削除できない履歴だけである。
- Azure Blob Storage、動画・音声ファイル保存、独自文字起こし、FFmpeg を現行または将来の実装対象として説明する記述がない。

## 8. 完了条件

- 新規の手動収集と予約収集が `metadata / chat_replay` だけで完走する。
- Worker と Gateway に字幕取得コードおよび字幕用設定が残っていない。
- Main API と OpenAPI に字幕 endpoint、字幕検索結果、字幕工程 enum が残っていない。
- PostgreSQL に字幕 schema が残っておらず、既存字幕データを持つ環境から安全に migration できる。
- Web UI に字幕の取得・状態・表示・検索が残っていない。
- サーバーが動画・音声ファイルを取得・保存・解析する計画または実装が残っていない。
- Azure Blob Storage の構成、依存、環境変数、接続、将来利用計画が残っておらず、永続化先が PostgreSQL に統一されている。
- YouTube 埋め込みプレーヤーとチャットの同期閲覧・検索・シークは維持されている。
- M3/M4 の E2E と repository-wide の `make check` が成功する。
- canonical documents、ADR、契約、完了デモが新しい方針と一致する。

## 9. リスクと対策

- **既存 Job が字幕待ちで停止する:** Worker 削除前に旧 Step の終端化 migration と状態再計算を入れる。
- **DB 削除が先行して旧コードが落ちる:** table 参照を先に除去し、schema 削除は後段コミットにする。
- **Gateway 全体を誤って削除する:** チャットリプレイ取得サービスとしての責務、health、認証、エラー分類を維持する。
- **「動画ファイル」と埋め込み動画を混同する:** ADR、UI、テストで、サーバー保存は廃止、IFrame 再生は維持と明記する。
- **将来用途として Blob Storage が残る:** 配信、コンテキスト、出典スナップショットを含む全用途を repository-wide に検索し、Azure Blob Storage の構成と記述を削除する。
- **検索 cursor の互換性が壊れる:** 単一種別化を段階的に行い、旧 cursor の扱いを API テストで固定する。公開クライアントが存在しないと確認できれば、互換層を設けず契約を簡潔にする。
- **ユーザーの未コミット変更と競合する:** 現在変更中の Web E2E と CSS を実装時に再確認し、その差分を保持して統合する。
- **ドキュメントだけ字幕前提が残る:** canonical documents を先に更新し、最後に repository-wide の用語検索とリンク検査を行う。

## 10. 実装開始時の確認事項

以下は本計画で既定値を置いた。実装前に異なる要望があれば変更する。

- YouTube 埋め込みプレーヤーは維持する。
- 既存の字幕データはバックアップせず削除する。
- Azure Blob Storage は用途を限定して残さず、システム構成から完全に廃止する。
- 永続化には PostgreSQL のみを使用する。
- Gateway サービスはチャットリプレイ取得用として維持する。
