# YouTube Stream Analyzer — プロダクト方針とロードマップ

## 1. 目的

YouTube配信から必要なデータを収集・蓄積し、切り抜き動画制作向けの分析と素材探索を支援する。

単なるコメント量の可視化ではなく、最終的には配信メタデータ・チャット・時系列指標を横断して、切り抜き候補の発見、確認、採用判断までを支援する。

## 2. 段階的な到達像

| フェーズ | 実現すること |
|---|---|
| Phase 1 | UIから終了済み配信を指定し、バックグラウンドでデータ収集する |
| Phase 2 | 配信URLを事前登録し、配信終了後に自動収集する |
| Phase 3 | 配信中のデータをリアルタイム収集する |
| Phase 4 | 収集データをダッシュボードで閲覧・探索・比較する |

実装はPhase 1から開始する。ただし、収集したデータを実際に確認できるよう、最低限の閲覧画面までをPhase 1の完成範囲に含める。

## 3. Phase 1 — 手動指定によるバックグラウンド収集

### 3.1 対象

終了済みのYouTube配信アーカイブを対象とする。

### 3.2 ユーザー操作

1. YouTube配信URLを入力する
2. 配信情報のプレビューを確認する
3. データ収集を開始する
4. 配信一覧で処理状況を確認する
5. 収集完了後、動画と収集データを閲覧する

### 3.3 収集対象

#### 配信メタデータ

- 動画ID
- タイトル
- チャンネルID
- チャンネル名
- サムネイル
- 公開日時
- 配信開始日時
- 配信終了日時
- 動画時間
- 説明文
- 配信状態

#### ライブチャット

- コメント本文
- 投稿者名
- 投稿者ID
- 投稿日時
- 動画開始からの経過時間
- メンバー、モデレーター等の属性
- スーパーチャット情報
- 絵文字、スタンプ情報

動画・音声ファイルと字幕・文字起こしは収集、保存、解析の対象にしない。ブラウザの YouTube 埋め込みプレーヤーは、チャットの時刻確認のために利用する。

## 4. Phase 1で必要な画面

### 4.1 配信登録画面

- YouTube URL入力欄
- 配信情報プレビュー
- 収集対象データの表示
- 収集開始ボタン

プレビューでは少なくとも以下を表示する。

- サムネイル
- タイトル
- チャンネル
- 配信日時
- 動画時間
- ライブ／アーカイブ状態
- チャットリプレイ取得可否

### 4.2 配信一覧画面

Phase 1のホーム画面とする。

- 配信情報
- ジョブ状態
- 現在の工程
- 進捗
- 最終更新日時
- 詳細、停止、再実行、削除操作

状態は単なる「処理中」ではなく、現在の工程と件数を明示する。

例:

- メタデータ取得完了
- チャット取得中: 12,450件
- 全工程完了

### 4.3 配信詳細画面

- 配信メタデータ
- YouTubeプレーヤー
- 時系列チャット
- 収集状態
- 取得件数
- エラー情報

チャットの行を選択すると、対応する時刻へプレーヤーを移動できるようにする。

## 5. システム構成

長時間処理はWebリクエスト内で完結させず、ジョブとしてバックグラウンド実行する。

```text
ブラウザ
   |
   v
Web UI / API
   |
   +-- 配信登録
   +-- 状態取得
   +-- 収集結果取得
   |
   v
データベース
   |
   v
ジョブキュー
   |
   v
バックグラウンドワーカー
   +-- メタデータ取得
   +-- チャット取得
   +-- 結果保存
```

### 5.1 Webアプリケーション

- 配信URL受付
- 配信情報プレビュー
- ジョブ登録
- 状態・結果表示
- 停止、再実行操作

### 5.2 バックグラウンドワーカー

- ジョブ取得
- YouTube情報取得
- データ正規化
- データベース保存
- 進捗更新
- エラー記録
- リトライ制御
- キャンセル確認

### 5.3 ジョブ状態

```text
queued
  -> preparing
  -> collecting_metadata
  -> collecting_chat
  -> completed
```

工程単位で状態、進捗、エラー、試行回数を保持する。

一部工程のみ失敗した場合は、成功済みの工程を再実行せず、失敗工程だけを再実行できる構造にする。

## 6. データモデルの中心

```text
Stream
 +-- CollectionJob
 |    +-- CollectionStep
 +-- ChatMessage
```

### Stream

YouTube配信そのものを表す。同じ動画IDは重複作成しない。

### CollectionJob

配信からデータを収集する1回の実行単位。同じ配信に複数回作成できる。

### CollectionStep

ジョブ内の個別工程を表す。

例:

- metadata
- chat
- analysis

### ChatMessage

動画開始からの経過時間を保持し、プレーヤーとの同期や時系列分析に利用する。

## 7. Phase 2 — 解析予約

配信URLを事前登録し、配信終了後にアーカイブから自動収集する。

予約状態の例:

```text
scheduled
monitoring
live
waiting_for_archive
collecting
completed
cancelled
failed
```

予定時刻だけを基準にせず、以下を確認してから収集する。

1. 配信が開始したか
2. 配信が終了したか
3. アーカイブとチャットリプレイが利用可能になったか

## 8. Phase 3 — リアルタイム収集

配信中に以下を時系列データとして保存する。

- ライブチャット
- 同時接続数
- 高評価数
- 配信メタデータの変化
- コメント投稿速度
- スーパーチャット
- 盛り上がり指標

この段階では高度な判定よりも、イベントログを欠損なく保存することを優先する。

## 9. Phase 4 — 切り抜き制作支援UI

### 配信タイムライン

時間軸上に以下を重ねて表示する。

- コメント量
- ユニーク投稿者数
- スーパーチャット
- 特定語句
- 盛り上がり候補
- ユーザーマーカー

### 区間詳細

- 開始・終了時刻
- 前後のチャット
- コメント増加量
- 代表コメント
- 関連区間
- メモ
- 切り抜き候補状態

候補状態の例:

```text
未確認
確認中
候補
採用
不採用
編集中
使用済み
```

## 10. 実装マイルストーン

### Milestone 1: 配信を登録できる

- URL入力
- YouTube情報プレビュー
- Stream保存
- ジョブ登録
- 配信一覧表示

### Milestone 2: バックグラウンドジョブが動く

- ワーカー
- ジョブ状態管理
- 進捗更新
- エラー保存
- キャンセル
- 再実行

### Milestone 3: メタデータを収集できる

- メタデータ取得
- DB保存
- 詳細画面表示

### Milestone 4: チャットを収集できる

- チャットリプレイ取得
- ページング
- 重複排除
- 時刻正規化
- チャット閲覧

### Milestone 5: 収集結果を操作できる

- 動画プレーヤー
- チャット同期
- 時刻ジャンプ
- 検索

## 11. Phase 1で実装しないもの

- AIによる「なぜ盛り上がったか」の判定
- 複数配信横断分析
- 配信者ナレッジベース
- 自動切り抜き生成
- 動画編集
- リアルタイム解析
- 高度なダッシュボード
- 本番クラウド構成の最適化

## 12. 最初の完成条件

> ユーザーが終了済みのYouTube配信URLを登録すると、サーバー上でメタデータとライブチャットがバックグラウンド収集され、処理状況を確認しながら、完了後にYouTube埋め込みプレーヤーと時刻同期したチャットを閲覧・検索できる。

この完成条件を基準に、画面仕様、データモデル、API、バックグラウンド処理を設計する。
