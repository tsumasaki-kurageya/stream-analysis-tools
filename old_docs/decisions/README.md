# Architecture decision records

Use ADRs for decisions that materially constrain architecture, data ownership, interfaces, deployment, security, or operational behavior.

## Lifecycle

1. Copy `template.md` to `NNNN-short-title.md`.
2. Assign the next four-digit number.
3. Set status to `Proposed` while discussing the decision.
4. Change status to `Accepted` when implementation may rely on it.
5. Use `Superseded by ADR-NNNN` when a later decision replaces it.

Do not create ADRs merely to document routine implementation details. Do not decide future milestone architecture before the decision is needed.
